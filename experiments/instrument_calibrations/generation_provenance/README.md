# generation_provenance

**Is the API-versus-open contrast an artifact of how the two arms were
generated?** An instrument calibration, not a finding about alignment. The
finding it qualifies lives in `../../passage_analysis/jakobson_space`; this
folder asks whether that finding is about the models or about the apparatus.

The contrast at issue: eleven commercial endpoints against 53 open checkpoints,
on surprisal and drift. The two arms differ in the model, and they also differ in
the deployment frame, the decoder, and what the vendor did that nobody recorded.
Each of those is a candidate explanation and each is measured here.

## What was asked, and what came back

    the deployment frame     frame_pilot.py, frame_pilot_score.py
    who can receive it       frame_eligibility.py
    hidden provider content  injection_probe.py
    decoder parameters       injection_probe.py (via litmod probe-sampling)
    nucleus truncation       top_p_sweep.py, top_p_sweep_score.py
    the instrument itself    support_probe.py
    the archive's wrapper    run_wrapper.py

**1. No provider injects a hidden system prompt.** `system="No"`, `user="Yes"` --
two tokens of content -- returns 4 (gemini-3.5-flash-lite), 6 (deepseek-v4-flash),
9 (claude-haiku-4-5) and 12 (gpt-5.4-nano) input tokens. Turn markers and role
delimiters. An injected block would be hundreds. It also explains an earlier
figure: pilot runs reporting 264 and 291 input tokens were carrying a JSON
SCHEMA, which is ours, not theirs.

**2. The frame lowers drift on every model tested** (see 5 for truncation, and
the section below for what the two together do and do not license). Our exact API system prompt,
run locally against a raw arm generated by the same code on the same device:

    SmolLM2-360M   drift -0.0192, sentence-controlled -0.0246
    Falcon3-1B     drift -0.0567, sentence-controlled -0.0432
    Qwen2.5-7B     drift -0.0997, sentence-controlled -0.0682

The CONTROLLED column is the one quoted anywhere else in this folder, and naming
it every time is load-bearing rather than tidy. `mean_drift` is a per-step mean
over a variable-length sequence, so it mixes any length change back in -- a fact
about the METRIC, not about whatever manipulation changed the length.

**AND THE CONTAMINATION HAS NO CONSISTENT SIGN**, so no rule of thumb recovers
one column from the other. Across these three models the control makes the
effect LARGER on one and SMALLER on two:

    SmolLM2   -0.0192 -> -0.0246   larger
    Falcon3   -0.0567 -> -0.0432   smaller
    Qwen      -0.0997 -> -0.0682   smaller

An uncontrolled estimate is therefore not "the controlled one plus a known
bias", it is a DIFFERENT QUANTITY. Section 5 shows the same thing in a third
form: there the uncontrolled sweep reads NULL on Qwen where the controlled one
is significant. Anyone reasoning from one column about the other will be wrong
in an unpredictable direction, which is why the column is named at every
appearance rather than once.

The length effect moves in three DIFFERENT directions across those models
(256->148 tokens, 182->256, 256->205), so the shared drift direction is not a
length artifact. The API-minus-aligned gap this would have to explain is
**+0.0085** -- three to eight times smaller, and pointing the other way.

**3. Sampling parameters were not what we asked for, and the Anthropic family
splits three ways.** Measured 2026-08-21 by rejection scan:

    claude-opus-5     top_p DEPRECATED, only 0.99 accepted   temperature discarded
    claude-sonnet-5   top_p DEPRECATED, only 0.99 accepted   temperature discarded
    claude-haiku-4-5  top_p REJECTED outright                temperature MEASURED to govern
    deepseek / gpt / gemini   top_p settable at any value, default unmeasured

**0.99 IS NOT RECORDED AS A DEFAULT.** The refusal reads "`top_p` is deprecated
for this model", which is not an equality test -- a surviving legacy value, an
inert no-op and a default all produce identical evidence. What governed those
1,200 passages is undisclosed. The reading was withdrawn after the full error
text was read; the first pass truncated it at 120 characters and cut off the
sentence that overturned it.

**4. The local arm carried a truncation nobody asked for.** `transformers 5.4.0
generate()` applies an effective `top_k=50` when the field is absent, while the
library default, the checkpoint's `generation_config` and the merged
`model.generation_config.top_k` ALL report `None`. Measured: `top_p=1.0` alone
never exceeds rank 47 in 200 draws; with `top_k=0` it reaches 7090; the same
distribution under `torch.multinomial` reaches 1772. `malignment.generate.DECODER`
now pins `top_k=0`.

That one invalidated a run in flight. Nucleus sizes at `top_p` 0.95/0.9/0.7 are
436/223/53 tokens, all larger than 50, so an unrequested `top_k` collapsed every
arm of the first sweep to one top-50 set. It would have returned a flat line
readable as "truncation does not move drift".

**5. Nucleus truncation LOWERS drift, monotonically, in all three models.** The
sweep, re-run after the `top_k` fix. Sentence-controlled drift against
`top_p=1.0`:

    top_p            0.95        0.9        0.7
    SmolLM2-360M   -0.0216   -0.0381*   -0.0922*
    Falcon3-1B     +0.0038   -0.0384*   -0.0670*
    Qwen2.5-7B     -0.0073   -0.0276*   -0.0423*     * CI excludes zero

Manipulation check passed first: truncation lowers reference surprisal
monotonically in every model (SmolLM2 5.61 -> 3.40, Falcon3 5.46 -> 3.92, Qwen
4.22 -> 3.39). Without that the drift column would mean nothing.

**It settles an argument that could not be settled by mechanism.** litmod
(largeliterarymodels) held that truncation should RAISE trajectory displacement:
mode-seeking decoding is ballistic rather than diffusive, so smaller steps
travel further. That is a claim about displacement from an origin, and
`mean_drift` is a mean of ADJACENT-sentence distances, which is close to
insensitive to it -- litmod granted the point once the metric was named. What
survived was their scaffolding mechanism, which does reach a step statistic: a
heading followed by a body sentence is a large step by construction. Measured,
it does not dominate.

**And it does not turn.** Their sharpest objection was that repetition at heavy
truncation could reverse the sign, leaving no single-signed correction at all --
the worst case, since a vendor default could then sit on either side. It is
monotone across 1.0 to 0.7 in all three models. A single-signed correction
exists.

**Qwen's uncontrolled drift is FLAT** (+0.0134, +0.0047, -0.0018, none
significant) while its controlled drift falls. Truncation raises sentence count
(13 to 14 at 0.7) and `mean_drift` averages over steps, so the uncontrolled
measure mixes the length change back in. Third time in this campaign the
sentence control has changed a verdict rather than confirmed one.

## WHAT THE TWO CONFOUNDS DO AND DO NOT LICENSE

An earlier version of this README said both confounds push the wrong way, so the
API drift result is "if anything understated". **That overreached twice** and
litmod (largeliterarymodels) named both.

**A signed confound protects a DIRECTION, not a MAGNITUDE.** Taken seriously,
"understated" says the deconfounded difference is 0.0085 plus something between
0.053 and 0.160 -- six to twenty times the observed value, arrived at by adding
two corrections neither of which is bounded. That is not a stronger finding; it
is a demonstration that the design does not resolve the quantity. The honest
sentence: **the observed difference is small relative to confounds acting
against it, so its SIGN survives and its SIZE is not estimated here.** That
point had already been accepted once and was drifted back off when the result
came out favourably -- a confirmation getting less scrutiny than a refutation
would have.

**And truncation's PRESENCE on the API arm is unmeasured.** Section 5 measures
what truncation does; it does not establish that any API model was truncated.
`top_p` is DEPRECATED on opus-5 and sonnet-5, and a deprecated parameter
plausibly does nothing -- so on 1,200 of the 6,600 passages there may be no
nucleus truncation from `top_p` at all. On deepseek, gpt and gemini the default
is settable but unmeasured, so presence there is unknown rather than assumed.

So the defensible statement is narrower than two confounds: **the frame pushes
the wrong way; truncation is unmeasured on the API arm and may be absent on the
Anthropic third of it.** The frame alone carries the direction and the second
argument was not needed.

Worth noticing which way that cuts: the deprecation finding cost a number this
seat wanted (0.99 as a default, withdrawn) and in exchange partially REMOVES a
confound rather than signing it. Fewer unpinned decoder fields on 1,200 passages
than were feared.

## The rule this folder keeps arriving at

**Settable is not governed, and neither is measured.** A parameter can be
accepted and ignored (DeepSeek's thinking mode), accepted only at one value that
may be inert (Opus), silently supplied by a library that reports it as unset
(`top_k`), or supplied by a vendor who publishes no default at all. "We set it"
is a claim about the request. Only a measurement is a claim about the run.

## What is NOT settled

The effective `top_p` default for deepseek, openai and google. The support test
cannot close it: `top_p=0.95` removes a sliver of TAIL mass, and n draws reveal
the head -- validated on a local checkpoint where 0.95 removes 99% of the nucleus
and 100 draws see a 4-type difference. A null from it would mean "n too small",
not "the default is 1.0", so no constant was sent for those three.

No decoder provenance is recoverable from the 6,600 already-generated passages:
the raw sidecar records responses, not requests.
